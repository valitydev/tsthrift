# TsThrift

A framework-independent toolchain under development for generating TypeScript types,
JavaScript Thrift clients, and form metadata from Thrift IDL, with a compatible
binary HTTP runtime and one CLI.

Initially, JavaScript is generated with the official Apache Thrift 0.24 compiler.
After the JS generator in `valitydev/thrift` is updated and validated, generation
will switch to that fork without synchronizing the entire fork with upstream.
The fork update does not block the initial implementation.
Generated JavaScript will use `bigint` internally; public TypeScript APIs will
continue to expose `i64` as `number`.

Generated packages will be ordinary JS/TS libraries with Promise-based clients.
Angular providers, RxJS wrappers, and form rendering belong to consumers.
The existing metadata format remains a compatibility requirement for `ng-thrift`.

## Status

The first generation pipeline is implemented: selected IDL files and their reachable
includes produce internal JS clients with bigint, public TS models with number-based
i64, and legacy-format metadata. Generation requires Apache Thrift **0.24.0**.

Output is an intermediate artifact. The HTTP runtime, public client implementation,
number/bigint conversion, and protocol package bundling are not implemented yet.
Generated Promise client interfaces describe the intended public API; they do not
instantiate working clients.

## Generate

Build the CLI with `vp run build`, then run:

```sh
node dist/cli.mjs \
  --input ./tests/fixtures/proto \
  --include ./tests/fixtures/dependency \
  --namespace example \
  --output ./generated \
  --compiler /path/to/thrift-0.24.0
```

Repeat `--include` and `--namespace` for multiple values. Without `--namespace`,
all top-level `.thrift` files in `--input` are entries. Include directories are
searched for referenced files only. `--compiler` defaults to `thrift` on PATH;
other compiler versions are rejected with an actionable error.

The result contains:

- `internal/`: unbundled CommonJS generated by the official compiler; it still
  requires compatible `thrift` and `uuid` runtime packages.
- `models/`: TypeScript models, constants, and Promise client interfaces.
- `metadata.json`: the existing `{ path, name, ast }[]` representation.
- `generation.json`: compiler version, generator options, and entry namespaces.
- `.tsthrift.json`: the manifest identifying owned generated files.

Use a dedicated output directory. Failed generation preserves previous output.
Regeneration rejects unmanaged directories and additional user files, then replaces
owned output and removes stale generated files.

## Current limitations

- Official object-backed maps support only string, integer, and enum key types in
  this pipeline. Other keys are rejected before output is changed.
- Full Damsel generation is blocked by `accounter.InvalidPostingParams.wrong_postings`
  (`map<Posting, string>`). Its `base` module was generated successfully in a local check.
- The legacy parser is pinned to `thrift-parser@0.4.2` to retain metadata semantics.
  Unsafe integral numeric literals are rejected rather than silently rounded.
  Referenced and structured constants are not emitted yet.
- Duplicate module basenames, colliding JS output names, and method arguments named
  `callback` are rejected. These need explicit resolution rather than overwritten output.
- Public `binary` types retain the existing `string` declaration; runtime binary
  representation remains an unresolved compatibility decision.

## Development

- Install dependencies:

```bash
vp install
```

- Run the unit tests:

```bash
vp test
```

- Run all tests, including real compilation and generated-model type checking:

```sh
THRIFT_COMPILER=/path/to/thrift-0.24.0 vp test
```

Integration tests are explicitly skipped when `THRIFT_COMPILER` is unset. The
compiler is installed separately; CI provisioning is still pending. Tests verify
generated source and CLI behavior, not HTTP round trips or browser integration.

- Build the library:

```bash
vp pack
```
